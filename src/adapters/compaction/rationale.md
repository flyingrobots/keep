# Compaction recovery preflight

Status: accepted for PR #107 integration.

The recovery driver may observe more than one retained stage. Discarding an admissible earlier stage before examining a later contradictory stage would destroy evidence during an invocation whose result is refusal. The driver therefore constructs an effect-free action queue for both staging artifacts and `head.next`, then executes that queue under the retained writer authority. The lower protocol capabilities still revalidate their requests when executing them.

An error loading the current catalog is not evidence that the store has never published. Only a missing `HEAD` at the `OpenHead` boundary supplies the uninitialized expectation; decoder, policy, missing selected artifact and other I/O failures retain their original typed causes. A valid generation-two candidate beside a corrupt current head demonstrates why deferring this distinction to the finalizer is insufficient: the planner otherwise emits an unrelated initial-generation error first.

The alternative of checking only `head.next` before the old sequential loop is rejected because every stage's planning can refuse. All requests must be admitted before any stage executes. Execution failure remains distinct from preflight refusal and does not imply rollback. This decision supplies no isolation guarantee against arbitrary concurrent out-of-band mutation; Keep's cooperating-writer contract and existing identity/evidence checks still apply.

This change preserves successful recovery of the existing interrupted publication phases. It introduces neither an on-disk record nor a cleanup namespace, and it does not change the incomplete-retention-stage refusal contract. The original preflight evidence alone does not establish execution-effect reporting; the separate execution laws below supply that evidence.

Stage lengths are admitted before reading their contents. Reusing the shared no-follow stage observation boundary preserves format ceilings, exact-byte fingerprinting and namespace checks instead of allocating an arbitrary file before deciding it is oversized. The queue and its cleanup rereads still materialize bounded stage bytes, and catalog verification has separate allocation limits; this decision makes no constant-memory claim.

Keeping only materialized bytes was insufficient: a fresh observation could accept a byte-identical replacement and discard evidence whose inode was never admitted by the plan. The queue now owns the original open handles as well as the bytes, verifies every queued observation before any action, and checks the affected observation again at execution. Retaining the handle also prevents the original inode from being recycled while evidence is in use. A metadata check cannot make pathname unlink conditional on identity; cooperating writer authority remains the supported mutation model.

## Execution failure is not an empty recovery

The shared compaction/ingestion driver now records prior actions only after their required directory synchronization succeeds. The first failed action returns a bounded execution report with its action, boundary and namespace effects, while retaining its original typed cause. Preflight errors carry no execution report and initiate no recovery mutation. A later action-level verification refusal has a report with no effects for that action, even if earlier actions completed.

The complete-stage path distinguishes the failed unlink capability (uncertain effects) from failures confirming absence or synchronizing its parent after successful unlink (known removal, unconfirmed durability). Lower truncated-discard and next-head-finalization errors retain whether the operation changed the namespace or observed an already-completed retry. Their sync errors map that outcome into the shared report; mutation-capability failures without effect evidence remain uncertain. Verification and candidate-file-sync failures precede namespace mutation by that action.

Inferring no effects from an empty earlier-completion list is rejected because the first action can fail after unlink. Inferring rollback from failed directory sync is rejected because unlink or rename has already succeeded. Dropping the original cause or returning a partial success receipt would conceal the failed boundary. The report instead stops execution and requires fresh observation for a retry. An idle observation is not retrospective proof of a previous failed synchronization's durability. No journal, new durable format, raw-namespace isolation promise or automatic retained-stage disposition is introduced.
