## Stage identity across preflight and execution

Claim: compaction recovery must not delete a byte-identical replacement for a stage observed during its preflight. A changed later stage must be detected before earlier cleanup. The owning boundary is the production compaction recovery driver, also used by durable writer recovery; the specified oracle is observed file identity and preservation of retained evidence before effects. These are product filesystem claims, not harness cardinality claims.

The medium filesystem laws `byte_equal_segment_replacement_is_preserved_before_cleanup` and `byte_equal_later_catalog_replacement_preserves_earlier_stage` run in `src/adapters/compaction/recovery_identity_tests.rs`. A synchronous callback replaces one stage after preflight and before execution, without sleeps or concurrent scheduling. Production calls the same driver with a no-op callback. The original file is held open while the replacement is created, preventing inode reuse from invalidating the fixture. The tests require the precise `FilesystemRecoveryStageError::Replaced` coordinate and preserve the replacement, both stage byte sequences and published `HEAD`.

[RED on unfixed revision `43e20c4`](m4-integration/107-stage-identity-red-43e20c4.txt) reports that both byte-identical replacements were silently cleaned. That revision adds only the tests and scheduling seam to `864f804`; the recovery policy and effects are unchanged. The [initial unformatted test run](m4-integration/107-stage-identity-red.txt) reproduces the same failures. The tests are retained until recovery is removed or a stronger deterministic schedule law subsumes their product claims.

The fix stores original opened observations with prepared actions, checks the entire queue before the first effect, and verifies each affected observation again before its action. Derivable cleanup retains the original handle through unlink and directory synchronization. Existing no-follow, namespace, exact-byte and format-length checks remain. The guard is not atomic with pathname unlink against arbitrary concurrent out-of-band namespace mutation; cooperating writers under Keep authority remain the supported model.

Two distinct negative controls calibrate the rejection and preservation oracles. [Removing whole-queue verification](m4-integration/107-stage-identity-queue-calibration.patch), while retaining action-level guards, [fails the earlier-stage preservation assertion](m4-integration/107-stage-identity-queue-calibration-2.txt): the later substitution is detected after the first stage has already been removed. The [first queue-control attempt](m4-integration/107-stage-identity-queue-calibration.txt) failed compilation because removing the call left unused code; it is not calibration evidence. Neither control changes expected output in the tests.

Restored [debug](m4-integration/107-stage-identity-final-debug.txt) and [release](m4-integration/107-stage-identity-final-release.txt) runs pass the identity laws and existing compaction laws, including the deterministic publication-interruption loop. ## Compaction and ingestion execution progress

Claim: a failing prepared recovery action must report prior durably completed actions separately from its own effects, stop execution and preserve the original typed cause. Admission refusal must remain distinguishable from execution failure. The owner and execution-policy limitations above remain unchanged. The specified oracle is refusal-is-not-rollback, measured through the public error report and actual filesystem namespace. This is a bug fix to shared compaction/ingestion recovery, not completion of GC or disposition error reporting.

`FilesystemCompactionRecoveryError::execution()` returns no report for admission refusal and otherwise names the action, boundary, prior completions and namespace effects. A failed unlink/replacement capability without sufficient effect evidence reports uncertainty; successful unlink followed by absence-check or parent-sync failure reports applied, unconfirmed effects. Lower discard/finalization synchronization errors contribute their preserved mutation-versus-retry outcomes from the previous delta. Completion is recorded only after the required directory synchronization succeeds. The first error returns immediately; the report cannot be passed back as a resume token.

| Deterministic failure schedule | Required public outcome and filesystem witness |
| --- | --- |
| Before complete-stage unlink | No namespace effect; all stages and current head remain. |
| After complete-stage unlink, before absence confirmation | Applied removal with unconfirmed durability; later stages remain. |
| Before complete-stage parent synchronization | Applied removal with unconfirmed durability; later stages remain. |
| Later truncated-catalog parent synchronization | Earlier segment cleanup completed durably; catalog removal applied without confirmed durability; next head remains. |
| Truncated next-head parent synchronization | Earlier stage cleanups completed; next head removed without confirmed root durability; current head unchanged. |
| Complete next-head root synchronization | Earlier stage cleanups completed; candidate replaced HEAD without confirmed root durability; next-head pathname consumed. |
| Actual failed Linux unlink after a directory substitution at the syscall handoff | Uncertain mutation result with exact EISDIR cause; substituted entry, retained original bytes, later stage and current head preserved. |

It does not assert atomic check/unlink isolation. Reopened recovery observes the remaining state; an idle observation is not retrospective certification of an earlier failed synchronization.
