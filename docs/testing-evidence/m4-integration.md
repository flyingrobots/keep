## Stage identity across preflight and execution

Claim: compaction recovery must not delete a byte-identical replacement for a stage observed during its preflight. A changed later stage must be detected before earlier cleanup. The owning boundary is the production compaction recovery driver, also used by durable writer recovery; the specified oracle is observed file identity and preservation of retained evidence before effects. These are product filesystem claims, not harness cardinality claims.

The medium filesystem laws `byte_equal_segment_replacement_is_preserved_before_cleanup` and `byte_equal_later_catalog_replacement_preserves_earlier_stage` run in `src/adapters/compaction/recovery_identity_tests.rs`. A synchronous callback replaces one stage after preflight and before execution, without sleeps or concurrent scheduling. Production calls the same driver with a no-op callback. The original file is held open while the replacement is created, preventing inode reuse from invalidating the fixture. The tests require the precise `FilesystemRecoveryStageError::Replaced` coordinate and preserve the replacement, both stage byte sequences and published `HEAD`.

[RED on unfixed revision `43e20c4`](m4-integration/107-stage-identity-red-43e20c4.txt) reports that both byte-identical replacements were silently cleaned. That revision adds only the tests and scheduling seam to `864f804`; the recovery policy and effects are unchanged. The [initial unformatted test run](m4-integration/107-stage-identity-red.txt) reproduces the same failures. The tests are retained until recovery is removed or a stronger deterministic schedule law subsumes their product claims.

The fix stores original opened observations with prepared actions, checks the entire queue before the first effect, and verifies each affected observation again before its action. Derivable cleanup retains the original handle through unlink and directory synchronization. Existing no-follow, namespace, exact-byte and format-length checks remain. The guard is not atomic with pathname unlink against arbitrary concurrent out-of-band namespace mutation; cooperating writers under Keep authority remain the supported model.

Two distinct negative controls calibrate the rejection and preservation oracles. [Removing whole-queue verification](m4-integration/107-stage-identity-queue-calibration.patch), while retaining action-level guards, [fails the earlier-stage preservation assertion](m4-integration/107-stage-identity-queue-calibration-2.txt): the later substitution is detected after the first stage has already been removed. [Reporting the wrong stage](m4-integration/107-stage-identity-diagnostic-calibration.patch) [fails the exact typed-coordinate assertion](m4-integration/107-stage-identity-diagnostic-calibration.txt). The [first queue-control attempt](m4-integration/107-stage-identity-queue-calibration.txt) failed compilation because removing the call left unused code; it is not calibration evidence. Neither control changes expected output in the tests.

Restored [debug](m4-integration/107-stage-identity-final-debug.txt) and [release](m4-integration/107-stage-identity-final-release.txt) runs pass the identity laws and existing compaction laws, including the deterministic publication-interruption loop. [Public preflight/allocation laws](m4-integration/107-stage-identity-public.txt) and the [durable writer recovery consumers](m4-integration/107-stage-identity-writer.txt) pass. [Workspace all-target/all-feature Clippy](m4-integration/107-stage-identity-final-clippy.txt) with warnings denied and [formatting](m4-integration/107-stage-identity-final-format.txt) pass. The public preflight run precedes removal of a redundant repeated derivable-stage guard; final debug/release compaction runs exercise the resulting guard placement. Full final validation and independent exact-head review remain required.

Commands are `cargo test --locked --lib adapters::compaction::`, its `--release` counterpart, `cargo test --locked --test compaction_recovery_memory --test compaction_recovery_preflight`, `cargo test --locked --lib adapters::durable::writer_tests`, `cargo clippy --locked --workspace --all-targets --all-features -- -D warnings` and `cargo fmt --all --check`. Each executes through the guarded copy runner in the reused Linux aarch64 worker, pinned Rust 1.96.0, on the bounded ext4 source/cache filesystem, with offline dependencies and `CARGO_INCREMENTAL=0`. The driver uses real filesystem handles and substitutions. Interrupted-publication tests inject failures at a port; these checks do not simulate physical power loss.

The shared source/cache filesystem is capped at 20 GiB, the worker at four CPUs and 8 GiB memory, and compilation at two jobs; host admission requires 50 GiB free. These are aggregate controls, not per-test deadlines, memory ceilings, egress sandboxing or a measured suite SLO. The existing resource-policy gate remains open, and #106's waiver is not extended. This delta claims no fresh calibration of every inherited assertion, exhaustive raw-mutation isolation, or execution-effect/durability reporting. Those acceptance limits remain explicit.
