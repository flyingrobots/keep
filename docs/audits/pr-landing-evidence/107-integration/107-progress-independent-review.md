## Finding — P4: Progress-law documentation overstates source-chain assertions

`docs/formats/segment-store-v2/compaction.md:72` says the medium progress laws require “preserved typed causes.” The four laws implemented by `src/adapters/compaction/recovery_progress_tests.rs:84–123` and the two head laws at `recovery_head_progress_tests.rs:50–82` and `115–131` inspect progress and filesystem state but never inspect `error.source()`.

Only the Linux unlink law checks the driver’s original I/O cause (`recovery_uncertain_tests.rs:59–66`). The lower synchronization laws check EIO at the lower executor boundary (`filesystem_recovery_stage_discard_tests/sync_failure_laws.rs:44–48`, `filesystem_recovery_next_head_finalization_tests/sync_failure_laws.rs:47–51`); they do not test that cause through the new shared driver.

Concrete consequence: losing or replacing the original cause while preserving the progress report on a complete-stage checkpoint failure, truncated-discard synchronization failure, or head synchronization failure would not fail those six progress laws, despite the documentation claiming otherwise. Static inspection currently shows correct cause preservation; this finding concerns the evidence claim.

Suggested fix: narrow the sentence to the projections actually asserted. State separately that the Linux unlink law checks EISDIR, the lower laws check synchronization causes, and the remaining shared-driver cause propagation was inspected. Alternatively, add and calibrate the corresponding driver-boundary assertions.
